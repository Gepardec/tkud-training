== Kontextabgrenzung

[[business-context-2]]
=== Fachlicher Kontext

Das System ATU / PDV verwaltet Mitgliederdaten, Veranstaltungen, Kampagnen, Zahlungen und Auswertungen (und noch mehr) für 17 österreichische politische Organisationen bzw. Mitgliederorganisationen. Es interagiert mit Endanwendern (Mitglieder und Administratoren der Mandanten), externen Systemen (Mailprovider, SMS-Gateways, Portale) und Identity-Providern (Keycloak). Die Migration ersetzt das monolithische Tomcat-Deployment durch multi-tenant-fähige Quarkus-Services je Domäne und ein modernes SPA-Frontend.

[[interface-details]]
==== Details der Schnittstellen

[[if-01-if-02-browser-to-system]]
===== IF-01 / IF-02: Browser zum System

*Partner:* Endanwender (Mitglieder und Administratoren der Mandanten)

*Zweck:* Zugriff auf die Anwendung — Mitgliederdaten, Veranstaltungen, Kampagnen, Zahlungen, Auswertungen

*Eingang (Alt):* HTTP GET/POST an Servlet-URLs

*Eingang (Ziel):* HTTPS REST/JSON an das API-Gateway → Quarkus-Domänenservices

*Ausgang:* HTML (Alt) bzw. JSON → SPA-Rendering (Ziel)

[[if-07-keycloak-integration]]
===== IF-07: Keycloak-Integration

*Partner:* Keycloak (Identity Provider)

*Zweck:* Authentifizierung und Autorisierung

*Eingang:* OIDC-Anmeldeablauf, JWT-Token-Introspection

*Ausgang:* JWT mit `tenant-id`-Claim, rollenbasierte Autorisierung
