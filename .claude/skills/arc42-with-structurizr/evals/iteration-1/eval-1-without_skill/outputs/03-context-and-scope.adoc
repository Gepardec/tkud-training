[[context-and-scope]]
== Kontextabgrenzung

[[business-context-2]]
=== Fachlicher Kontext

Das System ATU / PDV verwaltet Mitgliederdaten, Veranstaltungen, Kampagnen, Zahlungen und Auswertungen für 17 österreichische politische Organisationen bzw. Mitgliederorganisationen. Es interagiert mit Endanwendern (Mitglieder und Administratoren der Mandanten), externen Systemen (Mailprovider, SMS-Gateways, Portale, Bankdatei-Importe) und Identity-Providern (Keycloak). Die Migration ersetzt das monolithische Tomcat-Deployment durch multi-tenant-fähige Quarkus-Services je Domäne und ein modernes SPA-Frontend.

[[interface-details]]
==== Details der Schnittstellen

[[if-01-if-02-browser-to-system]]
===== IF-01 / IF-02: Browser zum System (Ziel-Zustand)

*Partner:* Endanwender (Mitglieder und Administratoren der Mandanten)

*Zweck:* Zugriff auf die Anwendung — Mitgliederdaten, Veranstaltungen, Kampagnen, Zahlungen, Auswertungen

*Eingang:* HTTPS REST/JSON an das API-Gateway → Quarkus-Domänenservices

*Ausgang:* JSON → SPA-Rendering

*Authentifizierung:* Bearer JWT (OIDC über Keycloak)

[[if-03-keycloak-integration]]
===== IF-03: Keycloak-Integration

*Partner:* Keycloak (Identity Provider)

*Zweck:* Authentifizierung und Autorisierung

*Eingang:* OIDC-Anmeldeablauf, JWT-Token-Introspection

*Ausgang:* JWT mit `tenant-id`-Claim, rollenbasierte Autorisierung

*Technologie:* OIDC / OAuth2, Authorization Code + PKCE

[[if-04-mailprovider]]
===== IF-04: Mailprovider-Integration

*Partner:* Externer Mailprovider (SMTP/API-basiert)

*Zweck:* Versand von Kampagnen-Mails, Empfang von Mail-Callbacks

*Eingang:* HTTP-Callbacks über den Message Broker

*Ausgang:* E-Mail-Requests über den Message Broker

[[if-05-sms-gateway]]
===== IF-05: SMS-Gateway-Integration

*Partner:* Externes SMS-Gateway (API-basiert)

*Zweck:* Versand von SMS-Kampagnen, Empfang von SMS-Callbacks

*Eingang:* HTTP-Callbacks über den Message Broker

*Ausgang:* SMS-Requests über den Message Broker

[[if-06-portalsysteme]]
===== IF-06: Portalsysteme-Integration

*Partner:* Externe Portalsysteme (z.B. Besucherportale)

*Zweck:* Austausch von Portal- und Besucherdaten

*Eingang:* HTTP-Callbacks (asynchron, über Message Broker)

*Ausgang:* Portaldaten (asynchron, über Message Broker)

[[if-07-bankimport]]
===== IF-07: Bankdatei-Import

*Partner:* Externe Bank-Schnittstelle

*Zweck:* Import von Zahlungsdateien (Encashment)

*Eingang:* Importergebnisse (ack/nack)

*Ausgang:* REST/JSON-Anfragen über den Encashment-Service

*Technologie:* HTTPS, REST/JSON

[[if-08-mobile-future]]
===== IF-08: Mobile / Dritte (künftig)

*Partner:* Zukünftige mobile Apps oder Drittsysteme

*Zweck:* Integration von Drittanwendungen

*Eingang:* REST/JSON (Bearer JWT)

*Ausgang:* JSON-Antworten
